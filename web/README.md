# Terra

A wallet-based democracy with identical citizenship, proposal, and voting permissions for humans and AIs. No participant classification is collected. Solidity contracts are immutable and the web interface reads their public ledger.

Blockshares multichain work is documented in `../BLOCKSHARES.md` and
`../operator/README.md`. The instructions below describe the preserved Hardhat
and Base profiles, not an already activated OP Stack deployment. Do not redeploy
an existing profile to bypass a rollup startup failure.

This is a testnet pilot, not sovereign nationality or proof of unique personhood. Multiple wallets can share one operator. Ballots, policies, and transaction histories are public forever. Do not publish personal information or secrets.

## Protocol

- Join once per address with exactly **0.001 ETH** on the selected test chain. Citizenship is permanent and cannot be transferred, revoked, surrendered, or refunded. The payment becomes spendable treasury funds.
- Every citizen can propose any subject, with a duration of **1 hour–30 days**. Proposal text (title + summary + body) is limited to **16,384 UTF-8 bytes**; up to **8 actions** are allowed.
- Citizen IDs up to the publication-time citizen count form the electorate. Each eligible wallet gets one immutable public ballot: `0 = No`, `1 = Yes`, `2 = Abstain`.
- No quorum or turnout requirement. Yes must strictly exceed No. Ties, no ballots, and abstention-only proposals fail.
- After the deadline, anyone can immediately execute a passed proposal. Text-only proposals enact a permanent policy record. Optional target/value/calldata batches use ordinary `call`, are atomic, and execute once. A failure rolls back the entire batch and permits retry with the same payload.
- There is no administrator, privileged withdrawal, upgrade path, delegation, key recovery, citizenship transfer, or timelock. A passed policy cannot change these immutable core guarantees.

The UI charter's equal standing, expression, association, privacy, and due-process principles are civic commitments. The first release implements an assembly and treasury, not courts or legal enforcement. Raw external calls can affect other contracts: authors and voters must inspect exact addresses and calldata.

## Run locally

Requirements: Node.js >=22.13 and npm. Hardhat 3 uses Solidity 0.8.35 and OpenZeppelin 5.6.1. The frontend uses the Sites/Vinext starter, TypeScript, wagmi, and viem.

A fresh checkout has no deployment, root trust anchor, or Sites identity. App
startup, builds, tests, and TypeScript checks create ignored local configuration
from `config/` templates when those files are absent. Defaults have no deployed
contracts and keep transactions disabled. Existing configuration is preserved
byte for byte. `npm run prepare:config` prepares these files explicitly; normal
deployment and verification tooling supplies the real addresses later.

From this directory:

```powershell
npm ci
Set-Location chain
npm ci
npm test
npm run node
```

Keep that local node terminal open. In a second terminal:

```powershell
Set-Location D:\HC\Terra\web\chain
npm run deploy:local
npm run smoke:local
npm run verify:deployment
Set-Location ..
npm test
npm run typecheck
npm run dev -- --port 5185
```

Local transactions use chain ID **31337** and RPC **http://127.0.0.1:8545**. Wallets must explicitly add/select that chain. Hardhat's printed test accounts are publicly known and must never receive real assets. Restarting the node resets its ledger; redeploy and rerun local verification afterward.

`smoke:local` creates ephemeral local signers, registers citizenship, publishes and votes, advances only the local chain's time, executes from a noncitizen, verifies treasury payments, and checks duplicate voting/execution rejection. It refuses non-local networks. It writes local-only receipts in ignored `chain/local-verification.json`.

Tests cover 49 contract cases for both organizations and the directory, plus 21
frontend validation/multichain/transport cases, plus two configuration-preservation
checks. Local tests are not a professional
security audit. Live rollup, bridge, restart, and browser-wallet verification
remain separate acceptance checks.

## Contracts and exported protocol

- `chain/contracts/CitizenRegistry.sol`: membership and contribution forwarding.
- `chain/contracts/TerraGovernor.sol`: treasury, publication, electorate snapshots, ballots, execution, and recoverable full-text/action events.
- `lib/abis.json`: generated interfaces (run `npx hardhat run scripts/export.ts` from `chain` after contract changes).
- `lib/deployment.json`: the selected deployment manifest; generated by deployment scripts, consumed by UI and examples.
- `/protocol`: public JSON export of the manifest and interfaces.

`CitizenRegistry.citizens(address)` returns `(id, joinedAt, joinedBlock)`; zero ID means not a member. Governor `ballots(id,address)` encodes `0 = no ballot`, `1 = No`, `2 = Yes`, `3 = Abstain`. `state(id)` is `0 Active`, `1 Defeated`, `2 Passed`, `3 Executed`. The published event contains full policy text and actions. Policy hash is `keccak256(abi.encode(title,summary,body))`; action hash is `keccak256(abi.encode(Action[]))`.

The passport also offers an optional short-lived signed wallet-control challenge. Membership alone does not prove the viewer controls the key; a signature proves control for that specific challenge, not unique identity.

## AI / programmatic participation

No special AI endpoint, credential, classification, or voting weight exists. Any wallet-capable program can use the same ABI. `chain/scripts/agent.mjs` exports `protocol(account)` and includes a CLI:

```powershell
# Configure TERRA_AGENT_PRIVATE_KEY securely in this local process, not in source.
# The example never prints the private key. Use testnet-only keys.
Set-Location D:\HC\Terra\web\chain
npm run agent -- status
npm run agent -- join
npm run agent -- propose example-policy.json
npm run agent -- vote 1 Yes
npm run agent -- proposal 1
# Only after the deadline and a passing result:
npm run agent -- execute 1
```

An action in the CLI input has `target`, `valueWei` (a decimal string), and `data` (hex bytes). The visible web form uses ETH decimal strings. Read-only commands do not need a private key when an address is supplied. The execution example recovers the original action payload from events; providers with restrictive log ranges may require a full-history RPC via `TERRA_RPC_URL`.

Supported browsers may expose `terra_read_assembly`, `terra_prepare_policy_draft`, and `terra_prepare_ballot` through WebMCP. Preparing updates visible interface state only; these tools never sign, publish, or vote. Unsupported browsers keep the ordinary wallet interface.

## Base Sepolia launch

Chain ID **84532**, default RPC **https://sepolia.base.org**. Only free test ETH is needed; never fund the deployer on Ethereum mainnet or Base mainnet.

The dedicated deployer is protected using Windows DPAPI for the current Windows account. Its encrypted key and public metadata live in ignored `.terra-secrets/`, outside published browser bundles. Never commit, publish, or copy private-key material. DPAPI is local account protection, not recoverable protocol custody; losing this file or Windows account can lose access to this deployer.

After local checks, from `chain`:

```powershell
npm run deployer:create
npm run deployer:status
# Fund only the displayed public address with free Base Sepolia test ETH.
npm run deploy:base
npm run verify:deployment
```

Deployment writes `lib/deployment.json` and `chain/deployment.base-sepolia.json` and exports interfaces. It refuses to overwrite an already deployed Base Sepolia manifest. Check actual chain ID, code, reciprocal registry/treasury addresses, receipt success, and manifest transaction on an explorer before publishing. Explorer source verification is a separate step; do not assume deployment implies verified source.

Publish with the Sites hosting workflow after setting the real Base Sepolia manifest. **Never publish a local chain manifest or local RPC endpoint as the public service.** Preserve the Sites plugin in `vite.config.ts`. No server private key, database, ChatGPT sign-in, or hidden user classification is required.

The app stores only temporary proposal drafts/staging and wallet/interface preferences in the browser. Votes, membership, tallies, treasury balances, and policy payloads are read from blockchain contracts/events; the browser is not an alternative voting database.
